# AGENTS.md (hoody-sdk/hub)

This file is public. It holds the rules for anyone, person or agent, who edits the Hub v3 app (`hoody-sdk/hub/hub/`): the web Hub a Hoody API server serves at `/auth/home`, the one-file `hoody-hub.html` and the terminal Hub. This file governs `hub/`; how an API server builds and serves the Hub is out of scope here. The page recipe (page contract, gate, list pages, shots, anatomy, kit-first rules) is [HUB-GUIDE.md](HUB-GUIDE.md); this page points to it for file-by-file detail.

- **Terminal:** the same pages also run in a terminal, through `X.term.tsx` siblings and the terminal kit. Before editing `src/term/**`, a `*.term.ts(x)` file or a file that has one, read [src/term/README.md](src/term/README.md).
- **Shared checkouts:** when others may be editing the same checkout, re-read every file right before you edit it, change it in place, and never replace a whole file you did not create.
- **No version-control writes** unless the person you work for asked for them. Read-only `git status|log|diff|show` is fine.
- **Secrets:** never read or print `.env` files, tokens, credentials, process arguments or environment.
- **Public text:** UI text, strings and fixtures name no internal host or request header. The default AI model wherever a default is needed is `hoody-ai/hoody-free`, never a third-party model. No telemetry, analytics or phone-home path. No IPv6 or ICMPv6 options anywhere in the Hub. Names the API returns (server names) show as returned; authored copy follows these rules.

## Where things live

Paths are relative to `hub/src`. The aliases are `@kit`, `@core`, `@app/*`, `@shell/*` and `@ask/io` (`hub/tsconfig.json`).

| Path | Owns |
|---|---|
| `pages/<id>/` | One page, discovered by glob from its `page.ts` manifest. File roles and the required files: HUB-GUIDE.md, "The page contract" |
| `kit/` | The only UI library pages use: layouts, overlays, forms, data (`DataTable`, `useDataView`), states, tokens (`tokens.css`), icons. Public surface: the `kit/index.ts` barrel |
| `core/` | Everything that talks to the world: routes, queries, mutations, change/attempt/hold machinery, sign-in, crypt, storage, streams. Public surface: `core/index.ts` |
| `shell/` | App frame: sidebar, top bar, command palette, Ask dock, lock screen. Never imports a page |
| `app/` | Router, page discovery, fixtures runtime, test and e2e helpers, and the shared `conformance*.test.ts` guards |
| `ask/` | The Ask/AI engine and its journal. Pages reach it only through `@ask/io` |
| `../scripts/` | The `hub:*` commands (`check.ts`, `shots.ts`, `new-page.ts`, `build.ts`, `build-single.ts`, `dev.ts`) and the lint rules (`scripts/lint/`) |
| `../templates/` | One scaffold per layout, kept compiling by `scripts/check-templates.ts`; `--run` (in a copy of the tree) also runs their specs |

## Boundaries (lint and guards)

- **ESLint** (`hub/eslint.config.js`): a page imports its own folder, the `@kit` and `@core` barrels, `@ask/io`, and another page's `links.ts` (a page's `fixtures.ts` and tests may also use that page's `fixtures.links.ts`). No page imports a UI or data library (`react-aria*`, `@tanstack/*`, `radix`). Pages never call `fetch`, `localStorage`, `sessionStorage`, `indexedDB`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `BroadcastChannel` or `document.cookie`; data goes through `@core` (`defineQuery`, `defineMutation`, `coreSource`). Page files may not import `@app/fixtures|testing|e2e|shots.types|router|pages|main|DevToolbar|PageStates`, except `data.ts` and `fixtures.ts` (`fixtures`), unit tests (`testing`, `fixtures`), specs (`e2e`) and `shots.ts` (`shots.types`). The shell imports no page (tests are exempt). Every user-visible string is a key in a `strings.en.json`: no literals in JSX, labelling props or object literals; an ellipsis lives in the string value. Lists use `useDataView` + `DataTable`; never hand-roll filter, sort or search.
- **Stylelint** (`hub/stylelint.config.mjs`): colours, spacing, radius and z-index come from `kit/tokens.css`; logical properties only; no dashed borders (one allowance: the side nav's item line).
- **Lint exceptions:** the DESIGN rules of both linters fail. A file a rule cannot fit gets an entry in `app/conformance/exceptions.ts`; an inline disable of a `hub/` rule fails `std.inlineDisable`.
- **Conformance scans** (below): no new deep `@kit/...` or `@core/...` import in pages; no viewport `@media` or `matchMedia` in pages (size from the frame with `@container`); every `Drawer` has a unique literal `resizeKey` such as `computers-create` (lowercase letters, digits and dashes, 3 to 49 characters, starting with a letter; a wrapper may forward its caller's key; `kit/overlays/Drawer.resizekeys.test.ts`).
- **Seams with their own guards:** only the journal door (`ask/journal/door.ts`) and the approver custody (`kit/agent/approver-custody.ts`) call `claimTickets`; only core reads a call's tickets or writes the approver-lease header; `core/` imports nothing from `ask/` or `kit/agent`. Outside `ask/journal/` code reaches the journal only through its index, and only `ask/data.ts` names the journaled routes. A page that keeps itself loaded while hidden (`useKeepPage`) uses nothing whose safety depends on route-change effects. A QR code that carries a secret is drawn by `QrSecret`.

## Standing rules

- **C9, unknown outcome:** a send whose outcome is unknown is shown as "This may have gone through" + one sentence + **Check again**. Check again only reads. Nothing is resent blindly, and an unknown outcome is never shown as failed. A hold frees only on a "proves" verdict on a fresh answer, or on a warned Dismiss from its own sender, of the hold that was shown; other senders' and accounts' holds are never freed. A page never uses a no-argument `settle()` or `dismiss()` to free a hold it shows; it passes the shown hold (`dismiss(vars, hold)`, or `held()` + `dismissHeld(row)`).
- **Attempts bind to their target:** capture the target identity (stable id + store/scope) at send and keep the attempt record outside the dialog and the render. While the attempt is unknown its target offers only "Check again", which reads the captured target, never the current props. A confirm dialog is bound to the target that opened it: a selection, capability or target change closes it and refuses confirm. Missing evidence stays unknown: never fill it from what the person typed.
- **Parse at the boundary:** every wire answer the Hub classifies (status, readiness, decision, outcome, frames) passes through one parser per wire shape, which checks the discriminator, the identity and every field read, optional fields included, and returns a typed value or unknown. The type has no raw fields; classifiers, cards and hosts take only it. Contradictory payloads are unknown. Tests: a table of real agent shapes (real status codes), at least one malformed row per field read, one contradiction row, and a mutant that drops a field check.
- **Secrets and ids:** a secret shows only in `SecretField`. A full 24-hex id never shows (`IdChip` / `maskId`). Credentials go only to agent calls.
- **Sign-out** purges through `clearAuthTokens` and nothing else, and only through `core/lifecycle.ts`: a sign-out captures the outgoing session and purges only while storage still holds that session, so a newer login is never purged. Never call a delayed `clearAuthTokens()` directly.
- **Errors:** every error a person sees takes the kit `error=` prop (words mapped from the code, plus Details with "Copy details for support"), or `showErrorToast`, or says why not in a `noDetails: <why>` comment. Raw API text never appears as UI text.
- **Fixtures:** sample names come from `fixtureWorld` (atlas, Ada, Personal, Acme client). Never invent computer, realm or account names.
- **Chat platforms:** wherever a page names Telegram, Slack, Discord or another chat platform, show that platform's official mark from `kit/icons.tsx`; never a hand-drawn lookalike.
- **Use the kit; do not fork it.** A gap in the kit is fixed in the kit, not copied into a page.

## The AI tab

- **Where it lives.** `pages/ai/` is the tab (manifest `page.ts`, routes `tab.tsx`; Models & keys, Agents, Automations and Knowledge are screens inside it). `parts/Pane.tsx` is the pane beside every screen, `parts/Conversation.tsx` the open chat at `/ai/c/<sid>`, and trim, close, delete and fork are `parts/TrimDialog.tsx`, `CloseDialog.tsx`, `DeleteDialog.tsx` and `ForkList.tsx`. `kit/agent/` is the conversation UI the tab and the Ask dock share (`ConversationView`, `SessionView`, `Composer`, `GateCard`, `ForkMenu`, `DetailsPanel`, `SessionTab`); `kit/agent/capability.ts` `can()` is the one table for what a chat may do. `core/agent/` holds the agent routes and the live, stop and approver calls. `ask/` is the engine and journal behind both the dock and the tab.
- **How a chat is reached.** The tab never imports `ask/`. `ask/index.ts` registers a read-only provider (`provideConversations`) and an active one (`provideActiveConversations`); the tab holds them through `kit/agent/conversations.ts` and `conversationsActive.ts`. A send, stop, decision, answer or check exists only on an active source, and while the journal, by-key recovery, the attachment lease or (for a Strict chat) the approver lease is missing `can()` answers `prerequisites`. The tab's only `@ask/io` imports are `parts/Conversation.tsx` (attachments) and `settings/rules/Session.ts` (`checkStarted`), and `auto/workflows/newChat.ts` (Resume in a new chat: `gatedCreate`, `checkStarted`, `capsOk`, `seg`, `routes.version`; its create uses the settings session's declared `sessionRoutes.create`). `kit/agent/` imports nothing from `ask/`, `pages/` or `shell/`.
- **C9 in the tab.** The rule under Standing rules covers every change the tab makes: send, Stop, trim, close, delete, rename, fork, and the model or agent switch in Details. The attempt lives outside the render, keyed by the chat and computer captured at the press (`parts/conversationAttempts.ts`, `trimAttempts.ts`, `closeAttempts.ts`, `deleteAttempts.ts`, `renameAttempts.ts`; for the Details switch a module store in `kit/agent/useLiveSession.ts`, keyed by computer, realm and chat, so closing Details or another tab and reopening it still shows the unproven change and refuses a second one); while it is unknown the chat offers only Check again, which reads the captured chat and never resends. After a lost answer a trim is proved done only when the chat holds exactly the kept turns (`parts/TrimDialog.tsx`). An unconfirmed fork is a stored record found by its create key, checked or hidden by that key (`kit/agent/forkList.ts`). Page tests pin this; no scan does.
- **No legacy.** The Hub, the API and the agent are released together. A reply from the agent is read in the current contract's shape only: no fallback when a header, field or route is refused, no version sniffing, no retry without a field, no parsing of an older response shape. A reply that lacks evidence the current contract carries is unknown under C9, never read as an older agent's answer.
- **Journal and tickets.** A journaled POST (create, turn, follow-up, stop, decision, answer) leaves only through `ask/journal/door.ts` (`mint`, `admit`, `post`): the entry is written and read back before core's single-use ticket is minted, and core refuses a call that lacks a ticket its route declares required (`core/ticket.ts`). A Strict chat's approver-lease capability lives only in `kit/agent/approver-custody.ts` and goes out as the lease ticket's header, written by core. Tab code calls none of these; it sends through its active source.
- **Guards.** `app/conformance/ask-io.conformance.test.ts` (pages reach Ask only through `@ask/io`); `kit/agent/agent.boundary.test.ts` (`kit/agent` has no engine); `core/tickets.conformance.test.ts` (who claims and reads tickets, the lease header, `core/` imports nothing from `ask/` or `kit/agent`); `kit/agent/approver.conformance.test.ts` (custody, who reaches the lease); `ask/journal/journal.conformance.test.ts` (single doors, storage keys, journaled routes named only in `ask/data.ts`); `app/conformance/noarg-recovery.conformance.test.ts`. The attempt rule and No legacy have no scan: a reviewer checks them.

## Standalone Hub (one file)

`bun run hub:build-single [--out <file>]` builds the whole Hub as one HTML file (default `dist/hub-single/hoody-hub.html` plus `.sha256`; hoody-sdk ships it) that runs from any https origin, from localhost or as a file, and drives a Hoody over HTTP. It prints the size raw, gzip and brotli. The served build (`hub:build`) is separate and unchanged.

- **Where:** `vite.single.config.mts`; `scripts/build-single.ts` (build, write, sizes) and `scripts/build-single-assemble.ts` (pure assembly and refusals); `src/standalone/` (entry, start decision, branded sign-in screen, password sign-in, device flow, access key, file memory guard). The origin seam is `core/origin.ts` plus shared.js's "The API origin" (`hubApiRoot`, `checkApiOrigin`, `standaloneChoice`, `setStandaloneApi`); `<html data-hub-standalone>` turns it on.
- **One file:** every script, style, font, icon and worker is inline. The meta CSP lists a sha256 per inline block, never `unsafe-inline`. The build refuses a `src`/`href` that is not `data:`/`blob:`, a stylesheet link, fixture markers, or a file over 14 MB. The file memory guard (`FILE_MEMORY_SCRIPT`) is always the first script.
- **Notices:** the file carries one HTML comment right after the CSP meta, never before `<meta charset>` (a file opened from disk has no other label, and a browser looks for it in the first 1024 bytes only). It holds the package's `THIRD-PARTY-NOTICES.md` (read from beside `hub/`), the Hub's `LICENSE` and the license of each inlined font family, named in `FONT_LICENSES` (`scripts/build-single-assemble.ts`), never listed from the folder; the build refuses a missing or empty one, or text that would end the comment. A new bundled library, font or mark gets its row in hoody-sdk's `THIRD-PARTY-NOTICES.md`; a new font family also its file in `FONT_LICENSES`. Test: `src/standalone/bundle.single.test.ts`.
- **Which Hoody:** served mode never changes (`hubApiRoot()` is `/api/v1`). Standalone, the file knows its Hoody (nobody types an address): shared.js `STANDALONE_ORIGIN`. `checkApiOrigin` accepts only listed origins: `STANDALONE_ORIGIN`; while `STANDALONE_ALT_ORIGIN` differs from it, also that one and `http://localhost|127.0.0.1[:port]`. Keep both as plain literals, each written once (`core/origin.test.ts` pins it); never split, build or stamp them.
  - A release build lists one origin, so its link chooses nothing. A fork that wants a second Hoody or localhost sets `STANDALONE_ALT_ORIGIN` to a different origin. In such a build the link chooses the alternative or `?hoody=localhost:<port>|127.0.0.1:<port>` (the accepted values are in `standaloneChoice`; shared.js parses the raw `location.search` once at load: exact key `hoody`, no decoding, the key twice = refused). Anything else is refused, the default used, and the card says so without the value. A non-default choice is named in a warn band in every state with "Use the built-in server" (the same file without the parameter, a new load). Never a fragment, message or cookie; one per page load; never changed while signed in (stored credentials keep their Hoody whatever the link asks).
  - `GET /api/v1/hub/config` (public, no credential) is read before every sign-in way and gives the realm and computer domains and `hub_file_min`. It is never skipped or derived: any failed read offers zero sign-in ways and one "Try again", whatever record is stored: no answer or a timeout is "Can't reach Hoody" (the connection), an answer that is not the config (non-2xx such as a 404, a wrong body) is "Hoody can't open this Hub right now".
- **Frames:** a page shown inside another page offers no sign-in: the card draws one sentence and "Open in a new tab" and reads nothing; `standalone/device.ts` and `standalone/token.ts` (`checkToken`, `openToken`) refuse before any request, and a frame check that throws counts as framed.
- **The card:** one centred card in `<main>` (`standalone/Card.tsx`: kit `CutFrame`, `--hx-card` inside, at most `--auth-card-w`): the kit `BrandMark` at `lg` (32 px mark and "Hoody Hub", hidden from assistive tech on its wrapper), the state's title as the one `h1` (focused on a state change, also `document.title`), its body, a quiet file-page line, no footer; under the card at most one line ("New to Hoody? Create an account"). Card and line are centred while they fit; the page scrolls (nothing fixed, no inner scrollbar). No stepper, no page header, no Back. A warn band sits directly on `--hx-card` (its fill is see-through). Behind the card the page ground carries the hoody.com grid (`standalone/HGrid.tsx`: faint 80 px lines and a small "H" per cell in `--hx-ink`, one `aria-hidden` SVG with no pointer events; a mark that would touch the card or the line under it, or that the screen's edge would cut, is hidden; under a mouse the cell's mark lights in `--hx-acc` and fades, and a cell the pointer left fades as a soft `--hx-acc-soft` tile; none of that under reduced motion or Performance mode). Focus: a state's first field, else its title; a link that chose another server or was refused focuses the ready card's title first (the band is its `aria-describedby`); every refusal hands the focus back to the field to fill again (the kit Form disables its fields while a request is out, so the browser drops the focus to `<body>`): Password on the sign-in step (also an empty password with the address filled), the code on the 2FA step, the address on the reset form, the key (or realm ID) on the access-key form. The kit SecretInput has no `focusOnError` or input ref, so those boxes are reached through a wrapper.
- **Sign-in:** exactly ONE primary, Sign in, the submit button of a real kit `Form` (Enter in either field submits; while a request is out it reads "Signing in…", react-aria renders it `type="button"` and the Form refuses another submit; an empty field sends nothing and says so). "Forgot password?" is a text action under it; "Create an account" is text in the line under the card, never a button beside Sign in. Under a line: one secondary button per provider the Hoody's `GET /auth/config` offers ("Continue with GitHub", "Continue with Google": `standalone/ProviderWays.tsx`, the kit Icon `github` / `google` as its one mark, GitHub first; none while that read is out or when it fails), then one closed `Disclosure` "Other ways to sign in" with two text actions: "Sign in on <site>" (the device flow on the Hoody's own page) and "Use an access key", which replaces the password form with the key's own form (`standalone/TokenSignIn.tsx` over `standalone/token.ts`, after the served login page's key sign-in; "Check the key" its one submit, "Back to sign in"; a confirm card names account, place, end and key name before anything is stored). 2FA follows the password (`standalone/PasswordSignIn.tsx` over `core/signin.ts`). No sign-in way is offered until the Hoody is named and its floor read; on an ok read the card always names the Hoody with the read's domains, never a stored record's. "Forgot password?" and "Create an account" (`standalone/Signup.tsx`) run here too; their emailed links open the Hoody's own pages, and the person signs in here afterwards. Sign-up checks the API's password rule before sending (`passwordFitsRule`, mirrors the API's own rule: change both together), keeps no password after the request, and opens the signup check on the Hoody's own page in a new tab (URL rebuilt on the chosen origin from the answer's `token.secret` fragment), retrying with the caller secret until it passes (31 min cap), as the served sign-up page does without its inline runner. "Create your account" shows the provider buttons under its form while sign-up is open (disabled while its request is out; a press empties the typed password).
- **Providers:** a provider answers only the Hoody's own origin (the file's place, `file://` included, is never a redirect target, and a popup reporting back would be a message channel), so a provider button starts the device flow (`standalone/device.ts`): the person finishes with that provider on the Hoody's own `/auth/device` page (Continue, then the provider; a new account can be made there too), and the file gets its session by the device code. The waiting card says only what to press there ("On <site>, press Continue, then Continue with GitHub."), which holds for a new account, an existing one, 2FA and closed sign-ups alike. When the Hoody does not run the device flow ('off'), the band says the provider cannot finish here and "Open <site>" opens the Hoody's own page in a new tab (`/auth/signup` from "Create your account", `/auth/login` from sign-in; built from the listed origin through the kit's `webAddress`, never a typed address). Sign-up closed: the Create card keeps its closed sentence and names no provider. A framed page offers none (the frame card reads nothing). No invite code rides a provider sign-up (the device leg takes none): the Hub's setup panel asks for it after sign-in (`core/setup.ts` `invite`), as for an account made without one.
- **Not bugs:** a browser holding a stored record of an origin this file does not list (an older file's, or another Hoody's) beside a session reads "Sign out first": the record is never used or rewritten. The old-file card at app start shows no choice band.
- **`core/signin.ts` is the one pre-sign-in helper** (an exception to "`api()` is the one request helper": `api()` needs a session). Only `POST /users/auth/login`, `/users/auth/2fa/verify`, `/auth/signup`, `/auth/forgot-password`, `/auth/resend-verification` and `GET /auth/config`, through shared.js `apiCall` as nobody (`anonymous`), never a `code_challenge`; typed outcomes only (no server text, no data); the 2FA temp token stays in the step object's private field; an attempt re-reads `apiOrigin()` before storing the pair and stores nothing if it changed or a newer attempt (or `cancelSignIn()`) superseded it.
- **`core/account-mail.ts` is the signed-in page's way to the same two mail routes** (`POST /auth/forgot-password`, `/auth/resend-verification`, for the account's own address; the Account page). Sent as nobody like `core/signin.ts`, typed outcomes only; it reads no browser global, so a page the terminal draws may import it (never `core/signin.ts`).
- **Opened as a file:** every local file shares one browser storage, so on `file://` the page keeps everything in memory: `localStorage` and `sessionStorage` are replaced, IndexedDB, Cache Storage and `BroadcastChannel` removed (`standalone/fileMemory.ts`). Closing or reloading signs out, and after a sign-in the Hub opens in place (`standalone/entry.tsx`). If the guard cannot install, the page signs nothing in.
- **Hand-off:** payments (`pay` routes) are refused unsent (`STANDALONE_HANDOFF`) and linked to the served Hub (`servedHubUrl`). An address someone else opens, or a Hoody server page, is built from `hubSiteOrigin()` or `servedHubUrl()`, never `window.location.origin` (the file's own place has no Hoody pages). Browser alerts carry the Hoody's icon or none (`alertIcon`).
- **Minified:** vite minifies the bundle and its CSS (production mode, no source map, no comments); `build-single.ts` also sends the four inline auth scripts through Bun's transpiler (`keepStrict` puts `'use strict'` back, as the API's served copies do) and `hub-fonts.css` through `minifyPlainCss`. A new inline block goes through one of them. `FILE_MEMORY_SCRIPT` stays as written (about 2 KB). Test: `src/standalone/bundle.single.minify.test.ts`.
- **Download:** the served Hub offers the file in the top bar's "Skills / SDK" menu and at the end of the Guide's "Build your own" (`pages/guide/parts/hubFile.ts`), only where `hubFileUrl()` (`core/origin.ts`) names an address: the API renders `<html data-hub-file="1">` while its build has the file (the API's `GET /auth/hoody-hub.html`, an attachment), and the one-file Hub never offers itself. It is saved through a link with `download`, never by navigating.
- **Known gaps:** share and copy links on the keys, logs, board and notifications pages still use `window.location.origin`.
- **Tests:** `src/standalone/*.test.ts(x)` (the link's choice: `FirstRun.choice.test.tsx`; frames: `FirstRun.framed.test.tsx`, `device.test.ts`, `token.test.ts`; the config read: `FirstRun.fileMin.test.tsx`; provider buttons: `FirstRun.providers.test.tsx`), `core/signin.test.ts`, `core/origin.test.ts` (`standaloneChoice`, the listed origins), `core/alerts-standalone.test.ts`, `core/lifecycle-realms.test.ts`. No committed browser smoke: load the built file from a second origin and from `file://` against a loopback fake API.

## Conformance gates

Run under vitest. A page-scoped check (`hub:check --page <id>`) runs that page's tests plus `app/conformance*`; the guards under `core/`, `kit/`, `ask/`, `shell/` and the pages-root tests run in the whole-Hub run. Before you call a change done or ask for a review, run conformance once whole-Hub (`HUB_CHECK_PAGE` unset). Most failing gates name the fix; never silence a check, and an `eslint-disable` needs a `-- reason`.

| Test | Enforces |
|---|---|
| `app/conformance.test.ts` | Page discovery, required files, a known `status`, strings tables, the six functional e2e tags of list pages, shots that perform the state they name, fixture-world names, `useDataView`-only lists, no second route for an endpoint core has, no raw U+2028/2029 |
| `app/conformance.std.test.ts` | `usePageShortcuts` for page keys, every `var(--x)` defined, barrel imports only, no viewport queries, `usePageLink`, no deprecated DataTable props, kit copy/states/meters/tags/`CodeBlock`, `countryFlag`, `literal` on data-bearing buttons and no page or Ask CSS case reset on a button, a control hidden only by a null page link (`!link`, never a link kind), Logs URLs through the Logs link helpers, unique spec locators (`.first()`/`.nth()` carry a reason comment), every page spec runs, chat names through the ChatNames slot, no machine names or internal request headers in strings, no inline disable of a hub/ rule, a well-formed exception list |
| `app/conformance.anatomy.test.ts` (+ `.detector`) | Page-layout debt per file and scope against the rows in `conformance.allow.ts`; `hub:check` runs it first |
| `app/conformance.<name>.test.ts` for `errors`, `datatable`, `textarea`, `spacing`, `surfaces`, `ringgap`, `pageboundaries`, `kitexports`, `lintflip` | Error details, DataTable search and refresh, themed textareas, overlay spacing, surface tokens, focus-ring gap, the `fixtures.links.ts` entry, every `@kit` import is a barrel export, the DESIGN lint rules fail, and their exception loader stays file-scoped |

| `core/{limits,forget-callers,tickets}.conformance.test.ts` | Reads stay within the published list limits; only `lifecycle.ts` calls the sign-out forget; the ticket and approver-lease seam |
| `kit/perf.conformance.test.ts`, `kit/qr/qr.conformance.test.ts`, `kit/agent/approver.conformance.test.ts` | No CSS escapes performance mode; secret QR codes wear the key tag; one home for the approver lease |

**Allow-lists only shrink.** Rows live in `pages/<page>/conformance.allow.ts` and `app/conformance/allow.shared.ts`. A new offender fails, and so does a row for code that is clean now (the no-argument recovery rows are the exception: a listed call that is gone passes): lower or delete the row in the same change. Adding a row needs a reason a second reader accepted (in your own fork: one you would defend).

## Commands

Run from the Hub package root: the repository's `hub/` folder, which holds the Hub's `package.json` and `bun.lock` (one level above this file). First time: Bun 1.4 or later and Node.js 22.12 or later, `bun install`, and `bunx playwright install chromium` for the browser checks; HUB-GUIDE.md, "Before you start", has the rest (the terminal step needs Linux; `--skip term` elsewhere). `HUB_AGENT=<name>` names your work dir, so parallel runs keep apart.

```sh
bun run hub:new-page <id> --layout list-detail --title "Title"   # starts dark (status 'hidden')
HUB_AGENT=<name> bun run hub:dev --page <id>                      # fixtures dev server; prints PID and URL
HUB_AGENT=<name> bun run hub:check --page <id>                    # anatomy, tsc, eslint, stylelint, vitest, Playwright
bun run hub:vitest hub/src/<path>.test.ts                        # targeted vitest (never node_modules/.bin/vitest: see below)
HUB_AGENT=<name> bun run hub:shots --page <id>                    # every state at every width
bun run hub:build                                                # production bundle (dist/public/auth/hub)
```

- Run `eslint` from the app folder (`cd hub && bunx eslint src/...`). From the repo root with `-c`, the page-boundary and restricted-import globs never match and errors slip through. A whole-Hub `tsc` needs `NODE_OPTIONS=--max-old-space-size=6144`.
- Start vitest through `hub:vitest` (or `hub:check`). Both pass node `--wasm-max-mem-pages=4096`. Without it, vitest's main process reserves 6 GiB of address space for three es-module-lexer copies, and a run under an address-space cap (`prlimit --as`) can abort with `bad_alloc`.
- Stop the dev servers you started when you are done.
