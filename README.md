Each computer hosts your sites, APIs, databases, scheduled jobs, desktop apps and AI agents without the usual setup and upkeep. Software installed with `apt` or Docker stays. Restore from snapshots or back up to another server.

Each new computer comes with the 20-service Kit by default. Every service and HTTP port has an HTTPS link to open on any device or call from code. [Bots](#bots) coordinate agents across computers.

GUI apps run on a desktop in a browser tab, with no client to install. Desktops, terminals, the editor, files and database tables also embed in your own page as an iframe ([embed guide](https://docs.hoody.com/guides/embed-urls/)).

Files follow you: open a computer's folders on your own machine, share them between computers, or add cloud storage.

Hoody is 100% HTTP. Accounts, computers, Kit services and Bots answer over HTTPS, so anything that sends an HTTP request can use them, even a small IoT device. Live streams such as terminals and voice also run over WebSockets. Use the Hub, terminals, SDK, CLI, AI chats, coding agents, Telegram, Slack, Discord, voice or URLs.

Each block below calls a Kit service at its own link. Open that link in a browser tab to see the same service:

```typescript
import { HoodyClient } from 'hoody-sdk';

const hoody = new HoodyClient({ baseURL: 'https://api.hoody.com', token: process.env.HOODY_TOKEN! });
const box = await hoody.withComputer(process.env.HOODY_COMPUTER_ID!);   // one of your computers

// Every service is a link: https://<project>-<computer>-<service>-<n>.<server>.computers.hoody.com

// terminal-1: run a command in terminal 1. Open its link in a tab to watch it run
const { stdout } = await box.terminal.run('df -h / && uptime', { terminalId: 1 });

// browser-1: a stealth Chromium inside the computer, built to pass as a regular browser, reads a page as Markdown
const { data: page } = await box.browser.page.getMarkdown({ url: 'https://news.ycombinator.com' });

// sqlite-1: a database that answers over HTTP, created on first use
const db = { db: 'watch', create_db_if_missing: true };
await box.sqlite.sql.run({ ...db, sql: 'CREATE TABLE IF NOT EXISTS visits (title TEXT, at TEXT)' });
await box.sqlite.sql.run({ ...db, sql: "INSERT INTO visits VALUES (?, datetime('now'))",
  params: [page!.title] });

// display-1: with an app open on display 1, click a text field at x, y, type, press Enter, then take a screenshot
await box.display.input.type({ x: 640, y: 63, text: 'hoody.com' }, { displayId: 1 });
await box.display.keyboard.press({ keys: ['Return'] }, { displayId: 1 });
const screen = await box.display.screenshots.capture({ base64: true, displayId: 1 });

// agent-1: the Hoody Agent splits one task across subagents that work in the background
const { data: session } = await box.agent.sessions.create({ tool_mode: 'orchestrator' });
const id = session!.session_id!;
await box.agent.sessions.turns.run(id, {
  text: 'Check ~/shop: run the tests, audit the dependencies, read the logs. One subagent each.',
}, { gatePolicy: 'auto_approve' });
const { data: subagents } = await box.agent.sessions.tasks.list(id);

// Bots: ask in plain words. The same Bot answers in Telegram, Slack, Discord and at its own URL
const { reply } = await box.agent.bots.ask('chief', 'Is the shop up? Tell me what fails.');
console.log(stdout, subagents!.items, reply?.text);
```

### Run anything

By default a computer runs full Debian 13 Linux with systemd and `apt`.

| To run | What you do |
|---|---|
| **A site or API** | Start it on a port. Use its HTTPS link or your domain. |
| **Containers** | Docker Engine, Compose and Buildx come with the Kit. The daemon starts the first time a command uses it. Kind, Minikube, K3s and Podman also run. |
| **A database** | Use built-in SQLite or install another with `apt` or Docker. |
| **A scheduled job** | Use the built-in cron, set from code. |
| **A program that must stay up** | Register it, and it restarts on failure. |
| **A desktop app** | Open it in a browser tab or an iframe. Click and type from code. |
| **A virtual machine** | Run Linux, Windows or BSD inside a computer on rented bare metal. See [Virtual machines](https://docs.hoody.com/foundation/servers/virtual-machines/). |
| **A bare-metal server** | Rent a whole physical server from 1 day and fill it with computers. Hoody manages it. See [Servers](https://docs.hoody.com/foundation/servers/). |
| **An AI agent** | Use the built-in agent and [Bot](#bots). Both keep working after you disconnect, and a Bot reports to Telegram, Slack or Discord. |
| **Your choice of AI** | Hoody Free is included. Or connect a ChatGPT plan, Claude via Claude Code, a provider API key or your own endpoint. |
| **Computers for customers or AI** | Give each a token that reaches only their computers. See [Realms](#realms-and-tokens). |

<details>
<summary><b>SDK</b></summary>
<br>

```bash
npm install hoody-sdk        # or: bun add hoody-sdk
```

Requires Node.js 20.19+ or Bun (ESM only). This sample signs in with an email and password. If you signed up with GitHub or Google, or your account uses two-factor authentication, create an API token in the [Hub](https://hub.hoody.com) and use `new HoodyClient({ baseURL: 'https://api.hoody.com', token: process.env.HOODY_TOKEN! })` instead. Save as `quickstart.mts`:

```typescript
import { HoodyClient } from 'hoody-sdk';

// Sign in to your account
const hoody = await HoodyClient.login('https://api.hoody.com', {
  email: process.env.HOODY_EMAIL!,
  password: process.env.HOODY_PASSWORD!,
});

// Take your first computer
const { data } = await hoody.api.computers.list();
const computer = data?.computers?.[0];
if (!computer) throw new Error('No computer found. Create one in the Hub or with `hoody computers create`.');
if (computer.status !== 'running') throw new Error(`The computer is ${computer.status}. Wait until it is running.`);

// Get a client for it, and run a command
const box = await hoody.withComputer(computer);
const { stdout } = await box.terminal.run('uname -a');
console.log(stdout);
```

```bash
HOODY_EMAIL=you@example.com HOODY_PASSWORD=... npx tsx quickstart.mts
```

<summary><b>Files and scheduled jobs</b></summary>

```typescript
await box.cron.entries.create('user', { schedule: '0 * * * *', command: 'date >> ~/hours.log' });
```

<details>
<summary><b>A web server at a link, on your own domain</b></summary>
<br>

> **Ask your AI:** "Serve ~/site on port 8080 on my computer, give it a short link, and tell me which DNS record to add for shop.example.com."

**In code:**

Get the web server's port link:

```typescript
console.log(hoody.getKitUrl('http', computer, { port: 8080 }));
```

The link contains 2 long IDs. Give it a short name with an alias:

```typescript
const { data: link } = await hoody.api.proxy.aliases.create({
  computer_id: computer.id, program: 'http', port: 8080,
  alias: 'ada-shop',                  // 3 to 61 lowercase letters, digits or hyphens, starting and ending with a letter or digit
});
console.log(link?.url);
```

If the name is taken, the call fails with 409 `ALIAS_IN_USE`. Pick another.

Point your domain's DNS `CNAME` at the alias. Hoody issues the certificate.

</details>

<details>
<summary><b>An AI agent on a computer, and a Bot that reports back</b></summary>
<br>

> **Ask your AI:** "Ask the chief Bot on my computer whether the shop is up, and have it run the tests and report what fails."

Sign the agent into your account once with an API token from the [Hub](https://hub.hoody.com):

```bash
hoody agent login -c <computerId>
```

```typescript
const { reply } = await box.agent.bots.ask('chief', 'Is the shop up? Run its tests and report what fails.');
```

<details>
<summary><b>A script as an API endpoint</b></summary>
<br>

> **Ask your AI:** "On my computer, make an endpoint at api/hello that answers { hello: name } from the query string, and give me its link."

**In code:**

A script you write into the computer answers at a link right away, with no build or deploy.

```typescript
await box.exec.scripts.write({
  path: 'api/hello.ts',
  content: 'return { hello: metadata.query.name ?? "world" };',
});
// GET https://{projectId}-{computerId}-exec-1.{server}.computers.hoody.com/api/hello?name=Ada
// -> { "hello": "Ada" }
```

Run it from the CLI: `hoody -c <computerId> exec api-hello --query-param name=Ada` (add `--refresh-scripts` if the CLI does not know the new script yet). Schedule it with an `@schedule` comment and cron expression.

</details>

<details>
<summary><b>A desktop app driven from code</b></summary>
<br>

> **Ask your AI:** "On my computer, open Firefox in a new terminal, go to github.com, and send me a screenshot of its display."

**In code:**

Start Firefox, then click, type and capture screenshots:

```typescript
await box.terminal.commands.run(
  { command: 'firefox https://hoody.com &', wait: false },
  { terminal_id: '100' },                                   // a new terminal: terminal 100 draws on display 100
);
console.log(hoody.getKitUrl('display', computer, 100));     // watch it in a browser tab
```

Tell a Bot what you want. It starts agents on your computers, brings you their questions and reports results. Agents can delegate to subagents.

Assistants such as Grok Bot, Muse and Manus also give you an always-on agent with a cloud computer, but that computer belongs to the vendor. A Hoody Bot does the same job with one big difference: it is hosted on your own servers, managed by Hoody. The Bot, its agents, the files they work on and the full conversation live on your computers. What leaves them is what you send out: requests to the AI you choose, and messages to the chat apps you connect.

Bring the subscriptions you already pay for: sign in with your ChatGPT plan, or use Claude Pro or Max through Claude Code. A provider API key works too. Every computer includes `chief`, the default Bot, and Bots and agents use the included Hoody Free AI by default, without setup or an API key.

| A Bot | How |
|---|---|
| **Runs agents** | Starts an agent on any computer you allow, follows it to the end and reports the result. |
| **Routes models** | Enable routing: light tasks use fast models such as Hoody Free, heavy tasks use stronger models. Automatic routing needs an OpenRouter API key on the computer; without one, tasks go to the heavy model. A Bot can also run agents on Claude Code. |
| **Keeps a conversation** | No new chat or manual compaction needed. Agents use fresh contexts to keep the Bot's conversation small. The Bot compacts automatically, preserving its identity, guardrails and full log. |
| **Follows guardrails** | Set limits such as "Only touch ~/shop. Ask before deploying." The Bot gives them to its agents and checks each task it hands out and each message it sends to an agent against them, before it goes out. The check runs on a model you configure, usually with a TypeSafe or OpenRouter API key on the computer. When no check can run, the Bot refuses the work, unless `guardrail_check` is `lenient` or `off`. |
| **Requests approval** | Agent approval cards arrive in chat with **Approve** and **Deny**. |
| **Reports automatically** | Choose a home chat and the updates to send it, such as completed work, approval requests and errors. |

| From | How |
|---|---|
| **Telegram, Slack or Discord** | Up to 8 chat apps per Bot. Only you can chat by default. Set the app's `dm_policy` to `pairing` or `allowlist` to let others in. |
| **Voice** | `hoody agent bots voice connect --id chief -c <computerId>` or an OpenAI Realtime client. |
| **Hoody Agent** | Bots tab in a terminal or browser. |
| **Code** | SDK: `box.agent.bots.ask()`. CLI: `hoody agent bots`. |
| **Other AI apps and trusted people** | A Bot URL such as `https://<label>.hoody.bot`, which works as an OpenAI, Anthropic or MCP endpoint. |

<details>
<summary><b>Create a Bot</b></summary>
<br>

> **Ask your AI:** "Create a Bot called shop on my computer. It may only touch ~/shop on staging and the database, and must ask before deploying. Then ask it to upgrade staging to Node 26."

**In code:**

```typescript
const box = await hoody.withComputer(process.env.HOODY_COMPUTER_ID!);   // where the Bot lives

// A Bot with guardrails for every agent it starts
await box.agent.bots.create({
  id: 'shop',
  role: 'Keep the shop running and tell me what breaks.',
  guardrails: 'Only touch ~/shop. Ask before deploying.',
  allowed_computers: [process.env.STAGING_ID!, process.env.DB_ID!],
  routing: { mode: 'auto', light: { model: 'hoody-ai/hoody-free' }, heavy: { model: process.env.HEAVY_MODEL! } },
});

// Ask in plain words. The Bot starts the agents and replies; their reports arrive later in its log.
// The guardrail check needs a checker model, usually with a key on the computer (see "Follows guardrails" above).
const { reply } = await box.agent.bots.ask('shop',
  'Upgrade the shop to Node 26 on staging, run the tests, and tell me what changed.');
console.log(reply?.text);

// The agents it started, and the computer each one runs on
const { data } = await box.agent.bots.listDelegates('shop');
```

See [Bots](https://docs.hoody.com/api/agent/bots/) and [chat apps](https://docs.hoody.com/kit/agent/chat-apps/).

### Realms and tokens

Realm tokens limit an AI agent, teammate or customer to a group of projects and computers. Lists leave out projects and computers outside that realm, and direct requests for them are refused. Each computer can belong to several realms.

<details>
<summary><b>Realm access and examples</b></summary>
<br>

| Realm use | Effect |
|---|---|
| **AI agents** | Operate and create computers inside the realm. Cannot see projects or computers outside it, or move computers out. |
| **Production and staging** | Staging CI deploys without API responses revealing production. |
| **Customers** | Tokens reach only their computers. |
| **External collaborators** | Share selected computers with freelancers, auditors or support engineers. Optional IP allowlist and expiry. Deleting tokens revokes access immediately. |

> [!IMPORTANT]
> Realms limit the account API, not computer links or networks. Secure links with [access control](https://docs.hoody.com/foundation/proxy/permissions/). Realm tokens cannot read your wallet but can spend if permitted. Give agent tokens no spending permissions.

<details>
<summary><b>Realm and token setup</b></summary>
<br>

No separate realm creation call is needed:

1. **Choose an ID:** Use any 24-character lowercase hex string, for example from `openssl rand -hex 12`.
2. **Add computers:** Add the ID to each computer's `realm_ids`, preserving other realms. Add it to the project's `realm_ids` too, so the token can see the project and create computers in it. Creating resources through `https://{realmId}.api.hoody.com` attaches the realm automatically.
3. **Create a token:** Set permissions, expiry and allowed IPs. Share it with the realm address.

> **Ask your AI:** "List the computers in realm 507f1f77bcf86cd799439011, then create an external_customer token for that realm."

**In code:**

Scope the SDK or CLI to a realm:

```typescript
const staging = hoody.withRealm('507f1f77bcf86cd799439011');
const { data } = await staging.api.computers.list();   // only the computers in this realm
```

```bash
hoody --realm 507f1f77bcf86cd799439011 computers list
```

Create a realm-only token. Use a client signed in with `HoodyClient.login()`, or a token that has the `resources.create_tokens` permission (no template grants it). With two-factor sign-in on, a signed-in client also passes `otp_code`, unless you turned that check off for tokens:

```typescript
const created = await hoody.api.auth.tokens.create({
  alias: 'Customer Acme',
  permission_template: 'external_customer',
  realm_ids: ['507f1f77bcf86cd799439011'],
  allow_no_realm: false,
});
console.log(created.data?.token);   // shown once
```

Templates: `full_access`, `external_customer`, `dev_team`, `finance_team`, `read_only`. Sign in with `hoody login --token <token> --realm <realmId>`. See the [SDK guide](./docs/reference/guides/sdk.md#realms-and-tokens-for-your-own-users).

</details>

### TypeScript SDK

ESM only, for Node.js 20.19+ (22.19+ recommended, see the [SDK guide](./docs/reference/guides/sdk.md)), Bun and browsers.

```typescript
import { HoodyClient } from 'hoody-sdk';

const hoody = new HoodyClient({ baseURL: 'https://api.hoody.com', token });
const { data } = await hoody.api.computers.list();        // the account: hoody.api.*

const box = await hoody.withComputer(computerId);         // one computer, by object or ID
const name = await box.files.readText('/etc/hostname');   // its Kit services: box.files.*, box.terminal.* ...
```

<details>
<summary><b>Conventions, sign-in, types and browser builds</b></summary>
<br>

- **Sign-in:** Pass a `token` as above, or sign in with `await HoodyClient.login('https://api.hoody.com', { email, password })`.
- **Responses:** Most methods return `{ statusCode, message, data }`, with the result in `data`. For a kit, `data` is the body exactly as the kit sent it. Helpers such as `files.readText()` and `terminal.run()` return the value directly.
- **Call options:** An options object for query parameters, `timeoutMs`, `retries` and `signal`. Its position depends on the method; follow the method's signature.
- **Lists:** Some paginated `list()` methods also have `listAll()` and `listIterator()`; check the method's signature.
- **2-factor auth:** `HoodyClient.login()` throws `TwoFactorRequiredError`. Complete sign-in with `await err.complete(code)`.
- **Token refresh:** Pass `onTokenExpired` to refresh self-managed tokens after a `401`.
- **Types:** Import the exported request and response types: `import type { DaemonProgramsCreateRequest } from 'hoody-sdk'`.
- **Browser bundles:** `dist/hoody-sdk.browser.min.js` (`window.HoodySDK`) and `dist/hoody-sdk.browser.esm.js` omit some Node.js helpers.

</details>

<details>
<summary><b>Errors and retries</b></summary>
<br>

Calls that fail over HTTP, the network or a timeout throw `ApiError`. Invalid parameters throw `ValidationError`, or `TypeError` for some options and helpers, and a few operations answer 200 and report the failure in their data. `isRetryableApiError` returns true for `408`, `425`, `429`, `500`, `502`, `503`, `504`, and `409` for busy file paths:

```typescript
import { isApiError, isRetryableApiError } from 'hoody-sdk';

try {
  await box.files.get('/nonexistent');
} catch (err) {
  if (isApiError(err)) {
    console.error(err.status);    // the HTTP status, or 0 for a network, timeout or parse failure
    console.error(err.code);      // the error code
    console.error(err.request);   // what was sent, with recognized secrets removed
    if (isRetryableApiError(err)) { /* may work if sent again; a change may already have run */ }
  }
}
```

The URL in `err.request` keeps its host, and an open computer needs nothing more than its address to be used. Keep logs that hold one private.

```typescript
await box.files.get('/bigfile', { retryOnStatuses: [502, 503, 504] });
```

See the [SDK guide](./docs/reference/guides/sdk.md) and [Errors, retries, middleware and token refresh](./docs/reference/guides/sdk.md#errors-retries-middleware-and-token-refresh).

</details>

### Command line

Run account and Kit operations from interactive shells or scripts.

```bash
hoody login                                   # sign in
hoody computers list                          # list your computers
hoody shell <computerId>                      # open a shell in one
hoody -c <computerId> files get /etc/hostname # read a file
hoody hub                                     # open the Hub (Linux)
hoody chat "what is a realm?"                 # ask a question about Hoody
```

<details>
<summary><b>Flags, streaming and credentials</b></summary>
<br>

- **Sign in:** `hoody login --web` (browser) or `hoody login --token <token>`.
- **Computer:** `-c <computerId>` for one command, or `hoody use -c <computerId>` to save a default.
- **Output:** `--output json` (also `table`, `yaml`, `wide`, `raw`).
- **Realms and scripts:** `--realm <realmId>` and `--non-interactive`.
- **Help and docs:** `hoody <command> --help`. Ask `hoody chat` without an account.

Event-stream commands with `--output json` print one JSON object per line; byte-stream commands such as `pipe receive` write the raw bytes. With `--non-interactive`, most commands fail instead of prompting. A few can still prompt on a terminal, such as `hoody agent login` (pipe the token in for scripts), `hoody chat` and `hoody local lock delete` without `--yes`. Sessions live in `~/.hoody/config.json`, created readable only by your user on Linux and macOS. `hoody local lock enable` encrypts credentials with a password. See [CLI authentication](./cli/CLI_AUTHENTICATION.md) and [CLI docs](https://docs.hoody.com/foundation/cli/).

</details>
